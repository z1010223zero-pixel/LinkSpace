# modules/input-sharing — 跨设备键鼠共享

架构 L4 层。P1 优先级，**本模块受许可证决策阻塞**。

## 两个子实现，不要混为一谈

| 子实现 | 场景 | 方案 |
|---|---|---|
| `win2win` | Windows ↔ Windows 边缘穿越 | 见下方许可证说明 |
| `win2android` | Windows → Android | 第一阶段复用 scrcpy 窗口内输入；无窗口穿越属第二阶段，需自研坐标系、边缘规则、焦点切换 |

两者不共用坐标系逻辑。

## 许可证阻塞项（务必先读）

方案 3.3 建议的 **Input Leap 已归档**（最后推送 2025-12，仓库 archived），且许可证 GitHub 无法识别。当前建议：

- 活跃替代品为 **deskflow**（GPL-2.0）
- 若走路线 B（保留闭源商业选项），**不复用其代码**，只研究算法与布局模型后自研
- 以独立进程调用可执行文件的方式存在法律解释空间，发行前必须评估

详见 `docs/license-inventory.md` 1.1。**在该决策落地前不要开始写代码。**

## 硬需求（方案 8.1）

- 有明确的退出快捷键与手动锁定
- **断开连接时必须立即恢复本机输入**，不能让用户鼠标卡在别处
