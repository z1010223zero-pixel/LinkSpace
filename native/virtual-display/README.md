# native/virtual-display — Windows 虚拟显示器（独立验证）

**高风险实验项目。独立于主产品推进，失败不得拖垮主进度。**

## 目标

让 Windows 识别一块虚拟显示器，用户可把窗口拖到 Android 平板上——是**真正的扩展屏**，不是普通投屏。

## 技术路线

Windows Indirect Display Driver（IDD）/ IddCx。从微软官方示例起步。

## 独立性要求（方案 9.3）

虚拟显示器涉及驱动与系统显示栈，不与 UI、文件传输混合开发。**本目录应视为独立实验仓库**，主产品只通过进程间接口调用。

## 前置问题（方案 9.4）—— 未回答前不投入完整开发

- [ ] 目标 Windows 版本能否稳定创建虚拟显示器？
- [ ] 能否获取并处理显示帧？
- [ ] Android 平板能否达到可接受延迟与画质？
- [ ] 睡眠、断网、重连后能否恢复？
- [ ] 驱动能否以用户可理解的方式安装、更新、卸载？

验证清单见 `docs/technical-validation.md` 第 3 节。

## 停止判据

若「创建虚拟显示器」或「获取显示帧」两项在 2 周内无法验证通过，建议暂停，降级为「高质量投屏式第二屏」。差异化放到体验层，而不是耗在内核态。

## 风险

驱动运行在内核态（见 `docs/threat-model.md` T8）：缺陷可致蓝屏或被利用提权。必须解决签名、安装、卸载、回滚与恢复方案后才可分发。
