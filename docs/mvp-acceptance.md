# LinkSpace MVP 验收标准

> 对应方案第十章。本文件把「验收标准」翻译成**可执行的测试步骤**，每项都能被独立验证或独立判定失败。
> 使用方式：每个候选版本按本清单逐项走查，记录 Pass / Fail / N/A（本版本不覆盖）与实际问题。

---

## 0. 前置准备

测试环境最小集合：

- 1 台 Windows 电脑（主设备）
- 至少 1 台 Android 手机（开发者选项、USB 调试可用）
- 可选：第 2 台 Windows 电脑（键鼠共享）、1 台 Android 平板（扩展屏幕）
- 局域网环境（普通家用路由器即可），准备一个隔离测试网段用于异常测试
- 测试样本：1 GB 大文件 1 个、1 KB 小文件 100 个、含中文与空格的文件名若干、0 字节文件 1 个

### 4.11 跨设备链路已验证（端到端测试）

`npm run verify:e2e`（`scripts/build-verify-e2e.mjs`）在同一进程里起两个完整
Host，走**真实**的 mDNS → WebSocket 控制通道 → TLS 数据面 → 信任清单门禁：

- mDNS 互相发现，TXT 里的能力位正确解析
- 配对码人工确认后双方建立信任，范围只含 `file`
- **已连接但未配对**的设备发起传输被授权门禁挡下
- 跨节点文件传输：落盘大小与 SHA-256 均与源文件一致
- 取消真实传播：接收方状态变 `cancelled`、`.part` 被清理、未产出最终文件
- 撤销信任后无法再发起传输

### 4.12 已验证范围与缺口

`npm run verify:transfer` 是同进程内发送方 + 接收方的环路测试，走真实 TLS +
HTTPS 分块路径，**不依赖第二台设备**，可重复运行。加 `--large` 触发 1 GB，
加 `--chunk=N` 覆盖块大小。

已覆盖：内容一致性（发送方算整体 SHA-256，接收方落盘前比对）、0 字节文件、
中文/空格/`#` 文件名、同名重命名、多块、断点续传、传输中取消并清理 `.part`、
未授权设备 403、并发、块级摘要校验（接收侧校验 `X-Chunk-Digest`，不符 400 拒收不落盘）。

**未覆盖，且不能算「已通过」**：

- 真实跨设备：两台机器间的 Wi-Fi 丢包、NAT、防火墙行为（端到端测试仍是同机双节点）。
- 取消的对端传播：`transfer.cancel` 需要控制通道，目前以事件形式暴露
  （`TransferManager` 的 `cancelRequested`），**尚未接入真实控制通道**。
- 发送方崩溃/退出后的残留 `.part` 清理。
