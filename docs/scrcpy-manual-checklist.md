# scrcpy 人工验证清单

对应 `docs/technical-validation.md` 2.6 节中「仍需人工验证的项」。
那份文档记录的是**自动化跑出来的结果**，本文件记录的是**必须真人看着设备
操作**的部分——这类项最容易在「觉得应该没问题」里被跳过，所以单独列成
可逐条勾选的表，每条都给出具体命令与判定标准。

> 原则：**未验证不等于通过**。表里留空或标 ⬜ 的项，在任何对外结论里
> 都必须表述为「未验证」，不能写成「支持」。

「把平板当第二屏来打字」的可用性，属于**决定是否继续投入**的判据之一。

## 4. 稳定性

| # | 检查项 | 操作步骤 | 通过标准 | 状态 |
|---|---|---|---|---|
| 4.1 | 关闭窗口后进程无残留 | 关闭投屏窗口 | `scrcpy.exe` 全部退出，无孤儿进程 | ✅ **已验证** |
| 4.2 | 断网后行为 | 投屏中关闭设备 Wi-Fi | 在预期时间内退出并给出可分类的错误码，不卡死 | ⬜ **必须人工** |
| 4.3 | 设备息屏 | 投屏中按电源键息屏 | 不崩溃；亮屏后恢复 | ⬜ |
| 4.4 | 设备重启 | 投屏中重启设备 | 适配器能识别设备离开并清理会话 | ⬜ |
| 4.5 | 长时间挂机 | 连续投屏 30 分钟 | 无内存持续增长、无画面卡死 | ⬜ |
| 4.6 | 应用退到后台再回来 | 设备上把投屏源应用切走再切回 | 画面恢复 | ⬜ |

进程残留检查命令（4.1）：

```powershell
Get-Process scrcpy -ErrorAction SilentlyContinue | Select-Object Id, StartTime
```

**4.1 已验证（2026-10-29，模拟器 `emulator-5554`）**：启动 scrcpy →
`CloseMainWindow()`（等价点关闭按钮）→ 进程在 4 秒内退出，退出码 0，
`Get-Process scrcpy` 返回 0 条。无孤儿进程。

**4.2 无法自动化，且必须人工执行**：无线调试本身走 Wi-Fi，脚本一旦关掉
Wi-Fi，adb 连接随之断开，就再也发不出「重新打开 Wi-Fi」的命令——
恢复动作只能在设备屏幕上手动完成。

执行与恢复步骤：

```bash
# 1. 投屏中，记下当前可发现的服务（后面要用来重连）
$ADB mdns services
#   adb-HA2CS105-NoeaQo  _adb-tls-connect._tcp  192.168.101.111:41931

# 2. 在设备上手势关掉 Wi-Fi（或用快捷设置面板）
#    观察：scrcpy 多久退出、退出码是多少、窗口是否卡死

# 3. 在设备上重新打开 Wi-Fi

# 4. 重连。端口可能变了，先重新发现再连
$ADB mdns services
$ADB connect 192.168.101.111:<新端口>
```

若第 4 步连不上，说明无线调试的配对已失效，需要在设备上重新走一次
「无线调试 → 使用配对码配对设备」。这是断网测试唯一的副作用，执行前先确认
有时间处理它。

## 5. 执行约定

- 结果直接回写到 `docs/technical-validation.md` 的 2.6 表，并注明设备型号与
  Android 版本——不同 OEM 的输入法行为差异很大。
- 未通过的项要在 `docs/roadmap.md` 里评估是否触发转向判据，而不是默默记一笔。
