Deskflow / Input Leap / Barrier / Synergy 的代码——原因见第 1 节。

   但实现要自己写，且要有独立的测试证据。
3. 若未来决定 LinkSpace 整体以 GPL-2.0 发布，本约束自动解除——
   但那是 `docs/license-inventory.md` 层面的决策，不在本模块范围内。
   决策项已登记为独立任务，见文末「阻塞项」。

## 2. 参考架构（只学结构，不抄代码）

Deskflow 系采用的模型，是所有软件 KVM 的共识解：

```
  ┌──────────── Server（键鼠物理接入的那台）────────────┐
  │  捕获本机键鼠  ──►  判定光标是否越过屏幕边缘          │
  │                        │                            │
  │                        ▼                            │
  │              把输入事件经 TLS 发给目标 Client        │
  └─────────────────────────────────────────────────────┘
                           │
  ┌──────────── Client（被控的那台）─────────────────────┐
  │  收到事件 ──►  用本机 API 重放（注入）                │
  └─────────────────────────────────────────────────────┘
```

关键设计点：

- **屏幕网格（screen grid）**：把各设备的屏幕按物理摆放排成网格，
  光标从 A 的右边缘出去，就出现在 A 右侧那台设备的左边缘。
  这个模型直观、可配置，也是用户对「一套键鼠」的心智模型。
- **边缘穿越的判定发生在 Server 侧**：Client 不判断自己该不该接管，
  全部由 Server 决定。单向决策避免了双方同时认为对方该接管。
- **键盘跟随鼠标**：键盘事件总是发给「当前光标所在」的那台设备。
- **剪贴板随切换同步**：切到哪台，哪台的剪贴板就被同步过去。

### 对 LinkSpace 的具体含义

我们已经有现成的基础设施，不必重造：

| 需要的能力 | LinkSpace 现状 |
|---|---|
| 设备发现 | ✅ mDNS（`_linkspace._tcp`） |
| 身份与信任 | ✅ 自签证书 + 指纹 + 信任清单 |
| 加密控制通道 | ✅ WebSocket over TLS（与数据面同端口，ADR-003） |
| 授权范围 | ✅ `TrustScope`，已预留 `control` 且默认不授予 |
| 剪贴板同步 | ✅ 已实现（阶段 3） |

**只缺两块**：本机的输入捕获与注入（Windows），以及屏幕网格配置。

## 3. Windows 侧的技术要点

### 3.1 捕获

| 方案 | 说明 | 取舍 |
|---|---|---|
| `SetWindowsHookEx(WH_MOUSE_LL / WH_KEYBOARD_LL)` | 全局低级钩子 | 能拿到所有输入，但钩子回调必须及时返回，且**不能**阻止事件继续下传（要「吞掉」事件需要额外手段） |
| Raw Input（`RegisterRawInputDevices`） | 从 HID 层直接读数 | `RIDEV_CAPTUREMOUSE` 可以把鼠标「锁」在屏幕内——这正是边缘穿越必需的；`RIDEV_INPUTSINK` 让后台窗口也能收到 |
| `GetCursorPos` 轮询 | 简单 | 拿不到按键，且高 DPI / 多显示器下坐标系易错 |

**推荐 Raw Input 捕获鼠标 + 低级钩子捕获键盘**。鼠标必须走 Raw Input：
只有 `RIDEV_CAPTUREMOUSE` 能让光标停在屏幕边缘而不真的移出去，
否则用户把鼠标往右推，光标就滑到显示器外面去了，边缘穿越无从谈起。

### 3.2 注入

- `SendInput`（`INPUT` 数组，鼠标用 `MOUSEEVENTF_MOVE` + `MOUSEEVENTF_ABSOLUTE`）
  是最直接的注入方式，键盘用 `KEYEVENTF_SCANCODE` 以避开布局差异。
- 鼠标移动要用**归一化绝对坐标**（0–65535 映射到主显示器），
  相对移动在多显示器与不同 DPI 下会累积误差。

### 3.3 三个绕不开的坑

1. **UIPI（用户界面特权隔离）**
   以管理员/更高完整性级别运行的进程，**收不到**低完整性进程注入的输入。
   表现是「控制别的窗口都正常，就是某个提权的窗口点不动」。
   彻底解决需要 `uiAccess="true"` 清单 + 代码签名证书 + 安装在受保护目录——
   这是 roadmap 里「代码签名证书」支出项的用途之一。
   第一版的诚实做法：**明确告知该限制**，不做任何绕过。

2. **安全桌面（UAC 弹窗、锁屏、Ctrl+Alt+Del）**
   这些在独立的 Winlogon 桌面上，任何用户态注入都到不了。
   必须明确：**键鼠共享在安全桌面上不生效**，这是设计限制而非缺陷。

3. **剪贴板只能有一套**
   Deskflow 类工具自带剪贴板同步，LinkSpace 也已经做了剪贴板同步。
   两套机制同时作用在同一台设备的剪贴板上，能构成
   `A → 设备剪贴板 → B → 设备剪贴板 → …` 的回环。
   **本模块必须复用已有的 `ClipboardSync`，不允许另起一套。**
   验证清单里已登记这一项（`docs/scrcpy-manual-checklist.md` 3.6）。

## 4. 协议草案

在既有控制通道上新增一组消息。字段风格沿用 `docs/protocol.md` 的信封。

| 类型 | 方向 | payload | 说明 |
|---|---|---|---|
| `control.request` | 控制方 → 被控方 | `{ sessionId, grid }` | 请求接管。`grid` 描述屏幕网格布局 |
| `control.accept` | 被控方 → 控制方 | `{ sessionId }` | **用户确认后才发送**，对应 `TrustScope.control` 的二次授权 |
| `control.reject` | 被控方 → 控制方 | `{ sessionId, reason }` | 拒绝，含未授权原因 |
| `input.enter` | 控制方 → 被控方 | `{ sessionId, x, y }` | 光标从边缘进入，坐标为归一化值 |
| `input.leave` | 控制方 → 被控方 | `{ sessionId }` | 光标离开，被控方隐藏本地光标 |
| `input.mouse` | 控制方 → 被控方 | `{ sessionId, x, y, buttons, wheel }` | 移动/按键/滚轮合并成一条，减少往返 |
| `input.key` | 控制方 → 被控方 | `{ sessionId, scan, down, mods }` | 用扫描码，不用虚拟键码（避免布局差异） |
| `input.stop` | 双向 | `{ sessionId, reason }` | 任一方终止 |

**授权模型**：`control.*` 与 `input.*` 一律要求对端持有 `control` 授权。
`control` **不随配对自动授予**——配对默认只给 `file` + `clipboard`，
`control` 需要用户在被控端单独确认（`control.accept` 即该确认的产物）。
这与 `docs/threat-model.md` T2 一致。

**节流**：`input.mouse` 天然高频，需合帧（约 120 Hz 上限）并在网络拥塞时丢弃中间帧、
只保留最新位置——丢弃中间帧不影响操作手感，堆积反而造成滞后。

## 5. 工作量评估

沿用 roadmap 的 10–25 人日，拆分如下：

| 工作项 | 人日 | 备注 |
|---|---:|---|
| Raw Input 捕获 + 边缘判定 | 3–6 | 多显示器坐标系是主要耗时点 |
| `SendInput` 注入与按键映射 | 3–6 | 含修饰键、滚轮、多按键同时按下 |
| 协议与状态机（含授权） | 2–4 | 复用既有控制通道 |
| 屏幕网格配置 UI | 2–4 | 拖拽摆放 + 持久化，可复用布局模块 |
| 兼容性与限制验证 | 2–5 | UIPI、安全桌面、多 DPI、远程桌面 |

**取上限的理由**：这类功能的 bug 几乎全部出现在「特定窗口 + 特定权限级别」
的组合里，自动化测不出来，只能靠人工矩阵。

**顺延判据**（roadmap 已写）：阶段 3 时间紧张时，优先保证阶段 2 产物的稳定性，
键鼠共享可顺延。它是 P1。

## 6. 验收口径

按 `docs/mvp-acceptance.md` 第 6、7 组。补充自定的三条：

1. 光标从 A 右边缘推出后，在 B 左边缘同高度出现，**不出现跳跃或偏移**。
2. 在 B 上输入英文与中文，结果与直接在 B 的物理键鼠上输入一致。
3. **明确记录**在哪些窗口上不生效（提权窗口、安全桌面），且该记录对外可见。
