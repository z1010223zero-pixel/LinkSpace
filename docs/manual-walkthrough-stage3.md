# 阶段 3 真机人工走查清单

对应 `docs/mvp-acceptance.md` 第 6/7 组中标注「留人工走查」的项，以及阶段 1 遗留的两项 UI 走查。

自动化环路（`npm run verify:input`、`npm run verify:clipboard`）已验证协议、状态机与授权门禁的正确性；本文件覆盖**必须真人看着设备操作**的部分——真实鼠标移动、真实键盘手感、真实断网时序。这些项最容易在「觉得应该没问题」里被跳过，所以逐条列成可勾选的表。

> 原则：**未验证不等于通过**。表里留空或标 ⬜ 的项，在任何对外结论里都必须表述为「未验证」，不能写成「支持」。

## 0. 环境准备

| 角色 | 要求 | 用途 |
|---|---|---|
| 电脑 A（控制端） | Windows 10/11，安装 LinkSpace master 最新构建（≥ f423ea4） | 发起键鼠控制 |
| 电脑 B（被控端） | Windows 10/11，同一构建，与 A 同一局域网 | 接受控制、弹确认条 |
| Android 真机 | 已安装 debug APK（阶段 2 产物），与 A 同一局域网 | 剪贴板 6.1/6.2 |

**通用前置**：

1. A 与 B 已互相配对（「已信任的设备」里能看到对方）；A 与 Android 真机已配对。
2. 两端主程序均从 master 最新代码构建：dev 模式 `npm run dev`，或重新打包安装。
3. B 的鼠标键盘可直接观察（走查时 B 屏幕要在视野内）。
4. A 的主屏分辨率与 B 不同（如 1920×1080 与 2560×1440），才能真实验证坐标比例映射。

**已知限制（预期行为，不是缺陷，走查时按此判定）**：

- **滚轮不跟随**：采集层用状态轮询（12ms），滚轮是事件不是状态，捕获不到；鼠标侧键（X1/X2）同样不跟随。
- **极速敲击可能丢帧**：轮询间隔内的快速按下+抬起可能合并，正常打字速度不受影响。
- **control 授权仅会话级**：每次控制请求被控端都会弹确认条；配对本身不授予控制权限；会话结束/断连/撤销后授权立即失效，再次控制需重新确认。
- **布局在会话间隙生效**：修改方位下拉不会打断进行中的控制会话，下次会话用新布局。

## 3. 手动发起与键鼠跟随（验收 7.2）

**在电脑 A 上操作**，B 的确认条与屏幕需在视野内。

| # | 检查项 | 操作步骤 | 通过标准 | 状态 |
|---|---|---|---|---|
| 3.1 | 请求弹出确认条 | A 点 B 条目上的「键鼠控制」 | B 主窗口顶部出现黄色确认条：「A 显示名」请求控制本机的鼠标和键盘，带「同意」「拒绝」按钮 | ⬜ |
| 3.2 | 拒绝路径 | B 点「拒绝」 | 确认条消失；A 无会话建立（可再发起新请求） | ⬜ |
| 3.3 | 同意进入控制态 | A 再次发起，B 点「同意」 | A 出现绿色状态条「正在用本机键鼠控制 B」；B 出现黄色状态条「A 正在控制本机的键鼠」 | ⬜ |
| 3.4 | 鼠标跟随 | A 移动鼠标 | B 屏幕上的光标平滑跟随，**无漂移、无跳变**；到达 B 屏幕任一边缘时光标停在边缘（不越界） | ⬜ |
| 3.5 | **跨分辨率坐标准确** | A（1920×1080）下把鼠标移到屏幕正中、四角、任务栏，逐一观察 B | B 侧光标落在**比例对应**位置（正中→正中），点击 B 上目标图标位置准确 | ⬜ |
| 3.6 | 左键/右键 | A 在 B 的桌面上左键点图标、右键点空白处 | B 侧选中、弹出右键菜单，行为与直接操作一致 | ⬜ |
| 3.7 | 键盘跟随 | A 打开 B 的记事本，打一段中英文混合文本 | 文字出现在 B 的记事本中，大小写、Shift 组合键正确 | ⬜ |
| 3.8 | 修饰键组合 | A 按 Ctrl+C / Ctrl+V / Alt+Tab | B 侧表现一致（Alt+Tab 在 B 上切换窗口） | ⬜ |
| 3.9 | 滚轮已知限制 | A 滚动滚轮 | **预期：B 侧不滚动**（记录确认限制存在即可，不算失败） | ⬜ |
| 3.10 | 控制端输入不被采回 | 控制期间在 A 上观察 A 自己的光标 | A 光标保持本地可控（控制事件只发往 B，不在 A 回放） | ⬜ |

`3.5` 是本组最关键的一项：两端分辨率不同时坐标映射错乱是键鼠共享的常见缺陷，且只在异分辨率下暴露。

## 4. 边缘穿越（验收 7.1）

**在电脑 A 上操作**，B 方位设为「在右侧」。

| # | 检查项 | 操作步骤 | 通过标准 | 状态 |
|---|---|---|---|---|
| 4.1 | 右缘触发 | A 鼠标快速移到屏幕右边缘 | B 弹出确认条（边缘触发走的与手动发起同一条链路，9.1 要求每次都提示）；B 同意后进入控制态 | ⬜ |
| 4.2 | 触发方向正确 | 把 B 改为「在左侧」，鼠标移到左边缘 | 同样触发，方向与布局一致 | ⬜ |
| 4.3 | 贴边不重复触发 | 鼠标顶在边缘不动 3s | 只触发一次请求，不连续弹 | ⬜ |

## 5. 退出机制（验收 7.4）

**在电脑 A 上操作**（除非注明），先建立控制态（B 已同意）。

| # | 检查项 | 操作步骤 | 通过标准 | 状态 |
|---|---|---|---|---|
| 5.1 | 全局快捷键退出 | 任意窗口焦点下按 **Ctrl+Alt+Space** | A 立即回到本机控制（绿色状态条消失），B 的状态条同步消失 | ⬜ |
| 5.2 | 快捷键全局生效 | 焦点在其他应用（如浏览器）时按 Ctrl+Alt+Space | 仍能退出（全局注册，不依赖 LinkSpace 窗口聚焦） | ⬜ |
| 5.3 | 按钮退出 | 重新建立控制，点绿色状态条上的「退出控制」 | 与 5.1 同效 | ⬜ |
| 5.4 | 被控端「拔掉」 | 重新建立控制，在 **B** 上点黄色状态条的「拔掉」 | 双端状态条同时消失，A 立即回本机 | ⬜ |
| 5.5 | 无卡键（快捷键路径） | 控制态下在 B 上按住一个字母键不放，同时 A 按 Ctrl+Alt+Space | B 上该键**不会卡住连打**（终止路径统一抬起全部按键） | ⬜ |
| 5.6 | 退出后事件停发 | 退出后立刻在 A 上移动鼠标、打字 | B 无任何反应 | ⬜ |

## 6. 断线与安全兜底（验收 7.5 + 9.1）

| # | 检查项 | 操作步骤 | 通过标准 | 状态 |
|---|---|---|---|---|
| 6.1 | 被控端断网 | 建立控制态后，**拔掉 B 的网线/关 B 的 Wi-Fi** | A 在心跳超时内回本机（≤15s，通常立即），输入不卡死；B 恢复网络后双端状态条已清空 | ⬜ |
| 6.2 | 无卡键（断线路径） | 6.1 断网瞬间 B 上有按住的按键 | B 侧无卡键（releaseAll 在断连清理中执行） | ⬜ |
| 6.3 | 控制端断网 | 建立控制态后拔 A 的网线 | B 的会话立即结束、状态条消失，B 键鼠恢复本地可用 | ⬜ |
| 6.4 | 撤销信任立即掐断 | 建立控制态后，在 B 上对 A 点「撤销信任」 | B 会话立即结束并抬起按键；A 端控制同步失效（双向） | ⬜ |
| 6.5 | 每次请求都提示（9.1） | B 同意一次控制并结束后，A **再次**发起 | B **再次**弹确认条——授权不因上次同意而记忆 | ⬜ |
| 6.6 | 重连后授权不复用 | 6.1 断网恢复后 A 直接点「键鼠控制」 | B 仍弹确认条，不自动恢复上次授权 | ⬜ |
| 6.7 | 未配对设备被门禁 | （可选）用第三台未配对电脑直连 A 发控制请求 | 请求被拒绝且 B/A 均无弹窗（自动化已覆盖，真机复核） | ⬜ |
