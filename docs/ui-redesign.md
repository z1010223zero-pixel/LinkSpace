# LinkSpace 桌面端 UI 重设计方案

> 分支：`decision/line2-accessibility-first`（本文档只存在于本分支，不动 master）
> 日期：2026-11-02。依据：对标调研 `~/workspace/linkspace-ui-benchmark/twindesk-todesk-ui-benchmark.md`（TwinDesk/ToDesk 官方截图逐张看过）与 UI 审计 `~/workspace/linkspace-ui-audit-2026-11-02.md`（App.vue 等 9 文件静态审读，27 条问题）。
> 原则：抄布局与信息架构，不抄品牌色与 logo；保持中文界面；现有 7 个功能入口一个不能少；只改表现层，不改 IPC、主进程逻辑、协议、功能行为。

---

## 0. 结论先行

现状是一页纵向滚动单栏：无导航、7 个区块平铺、两套设备列表并存、画面窗口与主窗口是两套视觉语言。新设计改成**左窄侧边栏 + 右内容区**的两栏式（TwinDesk/ToDesk 同构），导航按功能分 5 项；设备行统一为“状态点 + 系统图标 + 设备名 + 一行小字”；对称互控的核心是 Overview 页的**双向能力卡**（平板→电脑 / 电脑→平板，每行一个能力 + 蓝色 toggle）；画面窗口改成可折叠迷你工具栏 + 深色 token 体系。品牌色沿用 LinkSpace 现有的 `--accent #2f6bff`，不抄 TwinDesk 的 #0A84FF、ToDesk 的 #1677FF。

---

## 1. 对标结论：每家取什么、不取什么

### 1.1 TwinDesk 取什么

- **左窄侧边栏（约 200px）+ 右内容区**；导航按功能分，选中态整行 pill。
- **Overview 一页讲清“连着谁、延迟多少、双向开了什么”**：顶部本机地址卡、Nearby 设备行、中间连接可视化（两设备图标 + 渐变线 + `4 ms`）、下方两张并排方向卡（A→B / B→A），每行 Screen / Sound / Mouse and keyboard / Clipboard + 蓝色 toggle + ›。
- **延迟常驻三处**：侧边栏头（`设备名 · 4 ms`）、连接线上、顶部状态条。局域网产品的核心卖点，别只藏在详情里。
- **能力开关默认全关、每功能独立成页**，开页前先讲清楚它是干什么的（对应 LinkSpace“每次控制平板端确认”的原则）。
- **扩展屏用“分段控件 + 下拉选档位”**：Mode 用 Extend / Mirror 分段；分辨率/画质/码率下拉框，档位文案带定性描述（`1440p, sharper` / `Medium, 20 Mbps`），改尺寸后要点 Apply。
- **Receive / Share 两页分离**：看对方屏幕与把本机推出去是两套设置、两个入口，不合成一页。LinkSpace 正好是两个方向，各给一页。

### 1.2 ToDesk 取什么

- **设备行四要素**：状态点（绿在线/灰离线）+ 系统图标 + 设备名 + 一行小字（系统/IP/连接方式）；本机行加蓝色 `本设备` 标签；在线优先排。
- **选中设备的详情卡把高频操作摆成大图标阵**：控制 / 文件传输 / 剪贴板 / 扩展屏 / 断开，2×3 阵，第一屏全露出，不进二级菜单。
- **会话工具栏平时折叠**：顶部只留标题栏（设备名 + 延迟 + 画质徽章），中央小 chevron 展开，全屏自动隐藏。
- **工具栏按动词分组**：模式 / 控制 / 显示 / 文件传输 / 外接设备 / 屏幕 / 对话 / 结束远控；共享剪贴板放在“控制”组里用 toggle 开关。
- **连接就绪用一行绿勾文字**：配对成功后给一行状态确认，别只靠绿点。
- **断开显眼且至少放两处**：工具栏“结束远控”单列一组；主窗口也要有断开入口（对应“撤销信任级联断开”）。

### 1.3 不取什么

- 两家品牌色与 logo；TwinDesk 官网宣传图的深蓝紫渐变（营销图，不是 App 配色）。
- ToDesk 的“设备代码 + 9 位密码”连接模型（公网中继模型，LinkSpace 是局域网发现配对）；主界面底部插件推广横幅；设备行小字里的地理位置（局域网没有公网定位，写 IP 段/连接方式即可）。
- TwinDesk 14 项导航（全家桶定位，LinkSpace 控制在 5 项以内）；ToDesk“模式打包画质”（办公/兼容/高性能/游戏黑盒，LinkSpace 要看得见的分辨率/码率档位）。
- TwinDesk“画面窗口无工具栏、控制全在设置页”的极端分离：控制窗口至少留一个折叠式迷你工具栏（断开/剪贴板/画质/全屏）。

## 2. 现状问题摘要（审计 27 条里重设计必须修的）

1. 无导航、无分组，7 个区块平铺在一条纵向滚动流里；键鼠控制、发送文件藏在页面底部。
2. 两套设备列表并存（adb 网格 vs 信任行列表），同一设备两边都出现、入口不同，用户无法理解。
3. 区块按 `v-if` 整体消失，无空状态；信任列表为空时键鼠控制入口连同标题一起消失。
4. 行列表设备名用 12px 等宽字，像技术 ID；会话行只显示原始会话 id，没有设备名。
5. 异步操作全无进行中指示（配对/控制/发文件）；只有“刷新”有“扫描中…”。
6. “控制中”只在顶部横条，设备行上无标记；反向流进行中主窗口没有任何指示、无法从主窗口断开。
7. 剪贴板“关”态与中性 badge 撞色；主窗口与画面窗口的剪贴板开关长得不一样。
8. “键鼠控制”同文案两种行为（Win 是直接发起控制，Android 是开画面窗口）；两套分辨率档位口径不一致（投屏三档画质 vs 反向流四档分辨率）。
9. 配对码输入框全列表共用一个 `codeInput` ref，多设备时会串（功能 bug，随重设计修掉）。
10. 视觉：圆角 5 档、字号 12/12.5/13 三档近似值混用、间距无 token；`.btn--danger` hover 褪成灰色丢危险语义；focus 样式全站只有画布一条；`.code-field` 与 `.edge-select` 用了未定义的 `--text-primary` 变量（样式 bug，随重设计修掉）。
11. 画面窗口深色硬编码（`#111417` 等），与主窗口浅色 token 体系脱节；状态行混入调试信息（帧数/MB/关键帧重同步）。

## 3. 新布局

### 3.1 主窗口

```
┌──────────────────────────────────────────────────────────────────┐
│ ┌──────────────┬───────────────────────────────────────────────┐ │
│ │ LinkSpace    │ 顶栏：本机名（✎改名）· 在线 X/Y · 剪贴板开关 · 刷新 │ │
│ │ 本机 · 7 ms   ├───────────────────────────────────────────────┤ │
│ │ ──────────── │ ┌─ 概览 ────────────────────────────────────┐ │ │
│ │ ▸ 概览       │ │ 本机卡：名 · IP · [复制] · 就绪绿勾        │ │ │
│ │ ▸ 设备       │ │ 连接可视化：[本机] ═══ 7 ms ═══ [平板]    │ │ │
│ │ ▸ 屏幕       │ │ 方向卡A 平板→电脑：画面·键鼠·剪贴板·文件   │ │ │
│ │ ▸ 文件       │ │ 方向卡B 电脑→平板：画面·键鼠·剪贴板·文件   │ │ │
│ │ ▸ 设置       │ │ 设备行：● 平板名  Android · Wi-Fi · IP    │ │ │
│ │              │ └───────────────────────────────────────────┘ │ │
│ │ v0.1.0       │ 通知横条（分级 info/warn/danger，可多条并存）   │ │
│ └──────────────┴───────────────────────────────────────────────┘ │
│ 底栏：版本 · 会话数 · 传输数 · 端口/指纹                          │
└──────────────────────────────────────────────────────────────────┘
```

- **侧边栏 200px**：Logo + 本机名 + 延迟（`本机 · 7 ms`）→ 导航 5 项（概览 / 设备 / 屏幕 / 文件 / 设置），选中态整行浅蓝 pill（沿用 `--accent-soft` 底 + `--accent` 字，不抄 ToDesk 的 #DCE9FD）；底部版本号。
- **概览页**：本机卡（名 · IP · 复制按钮 · 配对成功后的就绪绿勾行）→ 连接可视化（两设备图标 + 渐变线 + 延迟）→ 两张方向卡（平板→电脑 / 电脑→平板；每行一个能力 + toggle + › 进详情；默认全关，行内一行小字说明能力是干什么的）→ 设备行列表（四要素 + `本设备` 标签）。
- **设备页**：左侧分组列表（最近连接 / 已信任的设备 / 局域网内其他设备，空分组显示空状态不消失）+ 右侧详情卡（选中设备：大图标阵——控制 / 发送文件 / 剪贴板 / 扩展屏 / 断开；下方键值详情：系统/IP/连接方式/延迟）。
- **屏幕页**：投屏设置（画质三档下拉 + 说明）与反向流设置（分辨率四档下拉 + 说明）分两组；扩展屏设置（Extend / Mirror 分段 + 尺寸下拉 + Apply）单独一组（线 3 未完成前显示“研制中”占位，不可点进假功能）。
- **文件页**：传输任务列表常驻（空时显示空状态），每行文件名、方向、进度条、速率、状态 badge、取消；接收确认常驻入口。
- **设置页**：本机名、剪贴板开关、端口/指纹、关于。危险操作（撤销信任）放设备详情卡里，点即执行改为二次确认。
- **通知横条**：分级 `info / warn / danger` 三种颜色；成功操作给 info 反馈并自动消失；错误给 danger 常驻到被关闭；多条可并存；控制中/被控中横条改成 danger/warn 分级（被控中用 danger 级，控制中用 ok 级），且对应设备行上同步显示“控制中”标记。
- **状态可见性**：所有异步按钮加进行中态（禁用 + 文案变“配对中…/连接中…/发送中…”）；反向流进行中时主窗口顶栏与对应设备行显示“正在看平板画面”标记 + 断开入口（调已有的 `stopReverseControl`）；在线计数口径与卡片状态一致（未授权单独一档，不算在线）。

### 3.2 画面窗口（反向流）

```
┌─────────────────────────────────────────────────────┐
│ 平板名 的屏幕 · 7 ms · HD          [⌄ 展开工具栏] [×] │
│ ┌─────────────────────────────────────────────────┐ │
│ │ 工具栏（折叠态默认收起，chevron 展开）           │ │
│ │ 显示：分辨率▾ 画质▾ 全屏 │ 控制：剪贴板 toggle   │ │
│ │ 断开（danger）                                   │ │
│ ├─────────────────────────────────────────────────┤ │
│ │                                                 │ │
│ │                 canvas 画面区                    │ │
│ │                                                 │ │
│ ├─────────────────────────────────────────────────┤ │
│ │ 1920×1080 · 控制中              帧数 · 码率（详情）│ │
└─────────────────────────────────────────────────────┘
```

- 标题栏常驻：设备名 + 延迟 + 画质徽章 + chevron + 关闭。
- 工具栏默认折叠（ToDesk 式），展开后分组：显示（分辨率/画质下拉）、控制（剪贴板 toggle）、断开（danger 单列一组）；全屏时自动隐藏。
- 深色主题改走 token（见 §5），不再硬编码；调试信息（帧数/MB/关键帧重同步）从状态行移入“详情”展开项，状态行只留分辨率与控制状态。
- 控制状态文案修歧义：`none` 时按 pending/failed 区分显示“等待平板确认…”/“控制未建立，仅查看画面”，pending 时给倒计时提示。

### 3.3 保留的功能入口（一个不能少）

配对发起 + 配对码提交/展示 + 拒绝/撤销信任；发送文件 + 接收确认 + 传输进度/速率/取消；剪贴板开关（主窗口与画面窗口外观统一）；Win 方位下拉 + 键鼠控制请求、Android 反向控制入口、被控侧同意/拒绝/拔掉、控制侧退出控制；反向流画面窗口及其画布交互；投屏画质三档与反向流分辨率四档（两处功能都保留，文案统一为“投屏画质”与“画面分辨率”，不假装是一套设置）；投屏停止、键鼠退出/拔掉、反向流断开、撤销信任。

## 5. 视觉规范（token）

- **品牌色不变**：`--accent #2f6bff`、`--accent-hover #2559d6`、`--accent-soft #eaf0ff`（LinkSpace 自己的，不抄两家蓝）。
- **新增间距 token**：`--space-xs 4px / --space-sm 8px / --space-md 12px / --space-lg 16px / --space-xl 20px / --space-2xl 24px`；所有 padding/gap 改走 token，禁止再散写 px。
- **新增字号 token**：`--text-xs 12px / --text-sm 13px / --text-md 14px / --text-lg 16px / --text-xl 20px`；删掉 12.5px 与 14.5px 近似值。
- **新增圆角 token**：`--radius-sm 6px / --radius-md 8px / --radius-lg 10px / --radius-xl 12px / --radius-full 999px`；删掉 3px logo 圆点（改 6px）。
- **深色 token**（画面窗口用，与浅色同名、挂在 `.theme-dark` 下）：`--bg #161617 / --surface #1e1e1f / --surface-2 #232325 / --text #e8eaed / --text-secondary #9aa0a6 / --border #2c3138`；强调色仍用 `--accent`，画面窗口的 `#3b82f6` 统一改回 `#2f6bff`。
- **状态色**：在线/成功绿、离线/警告黄、危险/被控红三档固定；离线不用黄（改灰 + “离线”文字），黄色只留给“进行中”过渡态。
- **交互态**：所有可点元素补 `:hover`；`.btn--danger` 补专属 hover（加深红，不褪灰）；全站补 `:focus-visible`（2px accent 描边）；禁用态 opacity 0.5 + 文字说明，不只靠透明度。
- **修掉的 bug**：`.code-field`、`.edge-select` 的 `var(--text-primary)` 改成 `var(--text)`；配对码输入框按设备拆成独立 ref；行内 `style="margin-top: 6px"` 全部收进 class。

## 6. 实施顺序与分工

- **A 线（主窗口）**：`App.vue` 壳 + 五页切换、`SidebarNav`、`DeviceRow`、`DirectionCard`、`DetailCard`、`SessionBanner`、`TransferList`、`DeviceCard`、`style.css`（含全部 token 与 bug 修复）。A 拥有 `style.css`。
- **B 线（画面窗口）**：只改 `ReverseStreamView.vue`（折叠工具栏、深色 token 消费、状态行文案、详情展开项）。B 不动 `style.css`（深色 token 由 A 在 `style.css` 里定义，B 只消费）；如需新增 token，先在本文档 §5 补记再由 A 落。
- **合并规则**：各用独立克隆，只动上面列出的文件；`style.css` 只 A 动；`docs/protocol.md` 与 `modules/protocol/protocol.json` 不动；不改 IPC、主进程逻辑、协议、功能行为；中文输入通道、scrcpy 收敛等别的功能线一律不动。
- **依赖**：不引入重型新依赖（无组件库、无路由、无图标库；图标用内联 SVG 或文字符号，与现状一致）。

## 7. 验收标准

- **功能**：§3.3 的入口逐项点名核对，一个不能少；配对码多设备不串；异步按钮有进行中态；反向流进行中主窗口有指示与断开入口。
- **构建与测试**（a1 上跑）：`npm run build`、`typecheck`（vue-tsc）、`verify:input`、`verify:binding`、`verify:protocol` 全部通过。
- **视觉**：a1 无显示器，界面视觉无法验证——提交信息与汇报里明确写“视觉效果待用户在 Windows 真机上验收”，不编造已目视检查。
