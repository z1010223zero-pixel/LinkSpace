# LinkSpace 开发路线图

> 对应方案第十一章。本文件增加了原方案没有的**阶段门限**与**转向判据**——每阶段结束时先判断要不要继续，而不是机械往下走。
> 时间估算为单人全职 + AI 辅助下的区间，不是承诺。

---

## 阶段 0：技术尽调（第 1 周）

**目标**：把两个最大未知项变成确定结论。

- 验证 scrcpy：USB / 无线 / 控制 / 剪贴板 / 多设备（清单见 `technical-validation.md`）
- 建立 IddCx 独立实验项目
- 核实依赖许可证（已部分完成，见 `license-inventory.md`）
- 确定发行路线（开源 vs 保留闭源选项）

**门限**：
- scrcpy 核心能力必须验证通过，否则 MVP 定义需重写。
- 发行路线必须有结论，否则 `modules/input-sharing` 无法开工。

**已知需修正项**：方案 3.3 建议的 Input Leap 已归档，候选改为 deskflow 或自研。见 `license-inventory.md` 1.1。

---

## 阶段 1：桌面原型（第 2 周）

**目标**：一个能统一管理手机投屏的桌面窗口。

- Electron + Vue 3 + TS 工程搭建
- 设备列表与连接状态模型
- scrcpy 启动 / 停止 / 参数 / 异常处理的适配层
- 多设备会话管理

**状态：已完成（2026-10-28）**

交付内容：

- `apps/desktop` 工程：electron-vite + Vue 3 + TS，`npm run dev` 可启动
- 主进程：adb 枚举、scrcpy 会话适配器、设备聚合、IPC 白名单网关
- 渲染层：设备卡片界面，显示型号/序列号/传输方式/状态，可启停投屏
- 无头验证 `npm run verify`：7 项断言全部通过
- Electron 版本定为 **37.10.3**，并记录 5 个本机环境踩坑

**门限结果**：

| 门限 | 结果 |
|---|---|
| 统一界面启停 2 台手机投屏 | ✅ 界面已能启停（GUI 交互待人工走查），无头验证覆盖会话生命周期 |
| 退出无残留进程 | ✅ electron 0 残留、scrcpy 0 残留 |
| 实测 Electron 资源占用 | ✅ 340 MB / 空闲 CPU 极低 → **ADR-001 复审通过，继续用 Electron** |

**转向判据**：未触发。Electron 在资源管理和窗口控制上均达标，无需评估 Tauri。

---

## 阶段 2：文件共享与配对（第 3–4 周）

**目标**：自己每天真正能用起来的第一版。

- mDNS 发现 + 配对 + 信任撤销
- 文件双向传输：进度 / 取消 / 校验 / 恢复
- 设备卡片拖拽布局与持久化
- Windows 安装包

**门限**：按 `mvp-acceptance.md` 第 1、2、4、5、9 组逐项走查全绿。

**状态：已完成（2026-10-29）**。mDNS 双向互通（含 Android NSD）、配对码流程
与信任撤销、双向分块传输（跨平台真机校验 SHA-256 一致）、NSIS 安装包与
SBOM 链路全部落地；两轮审查（desktop-review / project-review）的 P0/P1
已全部修复。第 9 组安全项达成：桌面 P3 加固（5350f65）与 Android 安全基线
（TLS 指纹绑定、服务端索证、DoS 限长）均于 2026-10-30 完成。

**注意**：Android 端在这一阶段才真正开始，第 2 周的原型可以只用 scrcpy + adb，不依赖 Android 客户端。

---

## 阶段 3：体验完善（第 5–8 周）

- 剪贴板同步（文本）
- 无线连接与断线恢复优化
- 跨电脑键鼠共享（先 Windows ↔ Windows）
- 投屏窗口、布局、快捷键打磨
- 安全与兼容性测试

**门限**：`mvp-acceptance.md` 第 6、7 组通过（若已实现）。

**状态：主体已完成（2026-10-29，f423ea4）**。剪贴板同步（双向 + 回环抑制 +
开关持久化）、Win↔Win 键鼠共享（边缘穿越 + 被控确认）、安卓→电脑远控、
断线即恢复本机输入均已合入 master。真机人工走查见
`docs/manual-walkthrough-stage3.md`。

**风险提示**：键鼠共享的投入容易被低估。如果这一阶段时间紧张，**优先保证阶段 2 产物的稳定性**，键鼠共享可以顺延——它是 P1。

---

## 阶段 4：扩展屏幕技术验证（第 2–4 个月）

- 虚拟显示器创建 / 删除
- 画面捕获与传输
- Android 接收端
- 触控回传与分辨率调整
- 断线、休眠、恢复

**门限**：`mvp-acceptance.md` 第 8 组。

**停止判据**（重要）：若阶段 0 的 IddCx 验证未通过（3.2.1 / 3.2.2 失败），本阶段应降级为「高质量投屏式第二屏」，不投入驱动开发。差异化可以放到体验层，而不是把时间耗在内核态。

---

## 阶段 5：公开测试与发布（第 4–8 个月）

- 安装 / 升级 / 卸载 / 错误恢复
- 第三方许可证合规（SBOM、NOTICE、版权声明）
- 设备兼容性测试
- 隐私政策、使用说明、故障排查文档
- 公开测试版本与反馈收集

**门限**：`mvp-acceptance.md` 全部 P0/P1 项通过，第 9 组全绿。
