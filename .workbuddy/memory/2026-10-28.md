## 第 1 周 scrcpy 技术验证（已完成，实测）

### 本机环境基线

- Windows **build 26300.9711 / 26H2**，但注册表 `ProductName` 仍写「Windows 10 Home China」（CoreCountrySpecific）——**是微软未更新的字段，实际为 Win11 26H2**。驱动开发勿以 ProductName 判断系统。
- x64；winget v1.29.380 可用（scoop 存在但未配 bucket）
- Node v22.22.2 / npm 11.0.0
- **未装 VS + WDK** → IddCx 验证的前置阻塞；家庭版无 Hyper-V，驱动测试需用 VMware（PATH 里已装）
- 已装 scrcpy **5.0.1** + adb 1.0.41（`winget install -e --id Genymobile.scrcpy`），路径：`%LOCALAPPDATA%\Microsoft\WinGet\Packages\Genymobile.scrcpy_Microsoft.Winget.Source_8wekyb3d8bbwe\scrcpy-win64-v5.0.1`
- 可用测试设备：**Redmi 24117RK2CC（Android 16，无线 TLS 已连）+ 模拟器 emulator-5554**。无平板（扩展屏验证的潜在阻塞项）

### 实测结论（全部通过）

- 采集链路：真机无线 3.3 MB/5s、模拟器 54 KB/4s，exit 0
- 窗口参数全可用：`--window-title` / `--window-x|y|width` / `--max-size` / `--print-fps`；渲染 direct3d11，解码 d3d11va，30–33 fps
- 多设备并发 OK，互不串流
- 退出码：0=正常，1=设备未找到（stderr 有可解析的 `ERROR:` 前缀行）
- 无头回归手法：`--no-window -r out.mp4 --time-limit=5`

### 踩坑记录

- 发行包里是 **SDL3（3.4.18）** 不是方案里写的 SDL2
- 录制时固定报 `WARN: [FFmpeg] track N: codec frame size is not set` —— 无害，别排查
- **官方包只附一份 Apache-2.0 的 LICENSE.txt，不含 FFmpeg/SDL3/libusb 的许可证文本** → 再分发必须自行补齐，是合规缺口
- FFmpeg 的 LGPL/GPL 取决于构建选项，尚未确认，不能默认 LGPL
- 无线设备序列号形如 `adb-xxxx._adb-tls-connect._tcp`，含特殊字符，构造命令行要转义
